## 4e. Research digest (complete after follow-up)

**Tokens.** W3C Design Tokens (v1, Oct 2025): three tiers, primitive → semantic → component;
semantic names must be intent-based ("text/subdued", not "text/gray").
Radix Colors: 12-step scale (1–2 background, 3–5 component states, 6–8 borders, 11–12 text) with
APCA Lc 60 / Lc 90 guarantees. Tailwind v4 ships tokens as CSS custom properties via `@theme`.

**Type scale.** Real ratios in shipped systems: Polaris **1.2**, Atlassian **1.2** (base 16px, body
14px/20px, everything on a 4px grid), Material 3 **15 styles** in 5 categories × 3 sizes, Carbon a
formula (`y₀ = 12px`), Tailwind default ~1.125–1.25. Butterick: **45–90 characters per line**.
`font-variant-numeric: tabular-nums` is the standard recommendation for data-dense UIs (Ant Design
PR #11567). Carbon/Material handle table density via density *modes*, not raw line-height values.

**Voice.** Polaris: sentence case, contractions encouraged, imperative verb + object on buttons, one
verb per button, never "Submit". Atlassian: brief, direct, action-oriented, plain language. Mailchimp:
active voice mandatory, plainspoken, lead with the main point. GOV.UK: short words ("buy" not
"purchase"), an A–Z of banned terms, no "please". **Convergent minimum set (3–6 rules): short plain
words · active voice + imperative verbs · sentence case · lead with the main point · no jargon ·
one reserved term per concept.**

**Glossary rot.** GOV.UK A–Z is the reference structure (100+ "don't say" terms with plain-English
replacements). Enforcement options found: **Vale** (prose linter, style packs, CI, `.vale.ini` — the
lowest-setup dedicated tool), textlint, alex, and **`eslint-plugin-i18next`'s `no-literal-string`**
(flags hardcoded UI strings, forcing them through a key catalogue). Published finding: **static
glossaries decay fastest without enforcement; living documentation generated from code plus a CI
block is what prevents rot.** Evidence that terminology drift causes real harm: calling one component
"button"/"CTA"/"action" confuses teams and undermines trust in the system (UXPin/NN-g).
*PM note: none of these tools should be adopted here — `tokens.test.ts` already proves a
zero-dependency Vitest source-scan does the same job at this scale.*

**Triage patterns.** Linear Triage: exactly four actions on hotkeys (1/2/3/H), no multi-select.
GitHub triage cards are designed to be scannable in **3–5 seconds**. j/k navigation from vi/Gmail.
Soft-delete plus an undo window removes the need for confirmation dialogs.

**Job-posting hierarchy.** Expected order: title → location → employment type → short summary →
2–4 responsibilities → team context → benefits. Seekers spend **~14.6s on requirements** and **~1
minute on a whole posting**; the initial scan is **6–7 seconds** before deciding to read on.
**Salary is the dominant abandonment trigger: 60% won't apply without it (Monster); postings with a
range get 36% more applications; 91% of new Indeed postings now include one.**

**In-domain source gap, to be flagged in the scorecard:** no ATS vendor (Greenhouse / Lever / Ashby)
publishes a design system, and no job-board usability study was found. The triage hierarchy
recommendations are transferred from generic review-queue patterns plus recruiting-side job-ad
guidance, not from validated seeker-triage research.
